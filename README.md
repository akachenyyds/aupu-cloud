# AUPU Cloud for Home Assistant

奥普 Q360T5-Pro 浴霸的第三方 Home Assistant 自定义集成，支持状态读取、照明、运行模式、风档、人感设置和预约。

**本地审阅候选，尚未发布。** 当前组件版本为 `0.3.0b9`；代码由个人设备接入工程整理，非奥普官方项目，与奥普及 Home Assistant 项目无隶属关系。仓库地址和 manifest 中的 GitHub 链接为拟发布位置，当前不代表仓库已经存在。

## 支持范围

| 项目 | 当前范围 |
| --- | --- |
| 设备 | Q360T5-Pro，云端产品 ID `10363`；其他型号不声明兼容 |
| Home Assistant | 本次隔离框架复验 `2026.9.4`，103 项通过；详见 [审阅报告](docs/REVIEW.md) |
| Python | 框架复验使用 Python 3.14；日常由 Home Assistant 管理运行环境 |
| 传输 | REST 控制 + 云 MQTT 状态；或缓存凭据的云 MQTT 读写 |
| 实体 | 每台 25 个实体，默认启用 24 个，外接灯默认禁用 |
| 安装 | 手工安装；准备了 HACS 仓库元数据，尚未在 HACS 实际安装或收录 |

两种模式都依赖奥普云与互联网。MQTT 模式的局域网检查只用于确认设备在线，**不是本地控制协议**。

## 功能

- 自带照明、小夜灯、外接灯光；自带照明只有开关，快速关开可能按设备原生行为轮换色温。
- AI 恒温暖（30–42℃，整数步长）、换气、吹风、除臭除菌、普通干燥、恒温干燥；换气与吹风分别支持 1–5 档。
- 人体检测、四个人感场景、感应夜灯、灵敏度、距离、无人待机和假日模式。人体检测不等于静止占用或人数检测。
- 暖房、换气、恒温干燥、除臭除菌预约：启停、时间、星期、实际时长；部分预约支持风档或目标温度。
- 只读设备测温、运行状态、在线状态和设备回报时间。设备测点温度不等于整个浴室的室温；E1 探头故障或无效字段不会继续显示旧测温。

参数与自动化示例见 [操作说明](docs/USAGE.md)。

## 安装前准备

1. 已在官方入口添加并能控制受支持的设备。
2. 拥有自己账户的有效 access token。**本集成尚无账号密码登录、扫码登录、令牌提取工具或自动续期。** 如果尚无有效令牌，目前不能仅靠安装本组件完成接入；不要向维护者发送令牌或抓包文件。
3. MQTT 模式另需设备固定的私有 IPv4 地址和真实 MAC；HA 主机必须能收到其 ICMP 回应并直接读取对应邻居 MAC。

跨 VLAN、NAT、桥接容器或缺少 ICMP 权限的环境可能无法完成局域网核验。Linux 实现读取 `/proc/net/arp`；macOS 分支使用系统 `ping`/`arp`。Windows 原生运行环境未验证。不要为通过检查而删除在线保护或关闭 TLS 验证。

## 手工安装与配置

1. 备份现有同名组件（如有），把仓库中的 `custom_components/aupu_cloud` 复制到 HA 配置目录的 `custom_components/aupu_cloud`。最终应存在 `custom_components/aupu_cloud/manifest.json`，避免多套一层目录。
2. 由 HA 安装 manifest 声明的依赖。首次装入自定义组件后，按 HA 的要求重启一次；本项目不包含向你现有 HA 发送重启或部署命令的脚本。
3. 在“设置 → 设备与服务 → 添加集成”搜索“奥普浴霸云端（实验）”。
4. 在 HA 本地表单中输入令牌，可自定义设备名称。表单默认选择 REST；选择 MQTT 后还需填写该设备的 IP 和 MAC。
5. 多台设备需逐台添加。配置流程检查设备归属；MQTT 设置验证局域网身份和云端状态，不发送设备控制。

### 两种模式的区别

| | REST（默认） | MQTT（实验） |
| --- | --- | --- |
| 首次发现设备 | 账户令牌 | 账户令牌 |
| 持久保存 | 账户令牌、设备标识及名称 | MQTT 凭据、设备标识/名称、IP/MAC；不保存账户令牌 |
| 运行时 | 账户 HTTPS 与云 MQTT | 云 MQTT 与局域网在线核验；不调用账户 HTTPS |
| 凭据失效 | 人工重新授权 | 用新的账户令牌重新取得 MQTT 凭据 |

HA 配置与备份中保存的凭据应视为秘密；密码样式输入框不代表存储被单独加密。详见 [隐私与安全](SECURITY.md)。

重新授权或通过“重新配置”切换传输时保留原配置项和实体身份。切换为 MQTT 会替换原配置数据以去掉旧 REST 令牌。操作前应先备份并核对目标设备。

## 控制行为与限制

- 只接受已识别功能和参数。控制前读取当前状态，确认在线，按设备串行合并指定字段。
- 使用独立请求标识及设备新回报确认执行；云端接受请求不直接等同于设备执行成功。
- 超时、断线或回执不明时不自动重发控制。读取断线可以进行一次有界重连。
- 单独调温不启动制热；AI 关闭时不能调节其目标温度。关闭温控只停止 AI 模式。
- 未识别的预约编码保留原值，不猜测写入。换档保持实际时长；超过新档上限时要求显式给出兼容时长。
- 云端状态存在延迟；30 秒轮询和局域网检查不能保证立即发现断电，也不证明设备即时热状态。

历史记录包括两台同型号设备的控制检查及一次约 10 分钟换气预约自然结束，不能外推到其他型号、全部预约周期或长期稳定性。账户自动续期仍未实现。原长期凭据观察曾提前失败，之后有限次数的成功查询不构成持续无故障证明。本次整理不新增真实设备验收。

## 开发与复验

完整框架测试需要 Python 3.14 和独立虚拟环境：

```sh
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-test.txt
python scripts/verify_project.py
python scripts/run_tests.py
```

只运行不依赖 HA 框架的客户端/编解码测试：

```sh
python -m pip install -r requirements.txt
python scripts/run_tests.py --unit-only
```

测试在临时目录启动隔离的 HA 对象，使用合成配置和 mocks；测试入口阻断外部网络连接，不读取现有 HA 配置或调用真实设备。安装依赖、漏洞数据库查询需要互联网，与测试执行分开。

```sh
python -m pip install -r requirements-audit.txt
python -m pip_audit --no-deps --disable-pip -r requirements.txt
```

上述漏洞查询仅覆盖两个直接安装依赖，不是整个 HA 环境的安全保证。依赖、许可和本次查询结果见 [第三方说明](THIRD_PARTY_NOTICES.md) 和 [审阅报告](docs/REVIEW.md)。
