# AUPU Cloud for Home Assistant

奥普 Q360T5-Pro 浴霸的第三方 Home Assistant 自定义集成，支持状态读取、照明、运行模式、风档、人感设置和预约。

**社区测试版 `0.4.0b1`。** 已在一个真实账户的两台 Q360T5-Pro 上验证短信登录、设备归属及云 MQTT 读取/重连。由个人设备接入工程整理，非奥普官方项目，与奥普及 Home Assistant 项目无隶属关系。

[![Checks](https://github.com/akachenyyds/aupu-cloud/actions/workflows/checks.yml/badge.svg)](https://github.com/akachenyyds/aupu-cloud/actions/workflows/checks.yml)

仓库：[akachenyyds/aupu-cloud](https://github.com/akachenyyds/aupu-cloud)。当前实际证据和未验证范围见 [审阅报告](docs/REVIEW.md)。

## 支持范围

| 项目 | 当前范围 |
| --- | --- |
| 设备 | Q360T5-Pro，云端产品 ID `10363`；其他型号不声明兼容 |
| Home Assistant | `2026.9.4` / Python 3.14.2：121 项隔离测试通过；另有真实短信与云 MQTT 只读验收，详见 [审阅报告](docs/REVIEW.md) |
| Python | 框架复验使用 Python 3.14；日常由 Home Assistant 管理运行环境 |
| 传输 | REST 控制 + 云 MQTT 状态；或缓存凭据的云 MQTT 读写 |
| 实体 | 每台 25 个实体，默认启用 24 个，外接灯默认禁用 |
| 安装 | 手工安装；准备了 HACS 仓库元数据，尚未在 HACS 实际安装或收录 |

两种模式都依赖奥普云与互联网。MQTT 模式的局域网检查只用于确认设备在线，**不是本地控制协议**。

## 功能

- 自带照明、小夜灯、外接灯光；自带照明只有开关，快速关开可能按设备原生行为轮换色温。
- AI 恒温暖（30–42℃，整数步长）、换气、吹风、除臭除菌、普通干燥、恒温干燥；换气与吹风分别支持 1–5 档。
- 人体检测、四个人感场景、感应夜灯、灵敏度、距离、无人待机和假日模式。人体检测不等于静止占用或人数检测。
- 暖房、换气、恒温干燥、除臭除菌预约：启停、时间、星期、实际时长；部分预约支持风档或目标温度。
- 只读设备测温、运行状态、在线状态和设备回报时间。设备测点温度不等于整个浴室的室温；E1 探头故障或无效字段不会继续显示旧测温。

参数与自动化示例见 [操作说明](docs/USAGE.md)。

## 登录与安装

本候选支持 **短信验证码登录（实验）**，无需手工抓取账户令牌。手机号与验证码仅在你提交 HA 私有表单后发送给奥普云。2026-10-28 已通过本人真实验证：短信登录、两台原设备身份匹配、领取云 MQTT 凭据、双设备读取及分别重连，共 10 次关联查询成功。此次验证没有访问现有 HA、发送设备控制或保存敏感值。详见 [认证说明](docs/AUTHENTICATION.md)。

1. 在官方奥普智享家小程序中确认设备已添加、能正常使用，准备本人绑定的中国大陆手机号。
2. 备份原同名组件，将 `custom_components/aupu_cloud` 复制到 HA 的 `custom_components/aupu_cloud`。依赖由 HA 根据 manifest 安装。
3. 首次装入自定义组件后按 HA 要求重启一次。在“设置 → 设备与服务 → 添加集成”搜索“奥普浴霸云端（实验）”。本版本尚未取得生产 HA 的实际安装/重载验收。
4. 选择“手机号验证码（实验）”或“已有账户令牌”。打开菜单不会发短信；提交手机号表单才会请求一条验证码，超时不会自动重发。
5. 完成登录后选择设备。MQTT 模式还需填写固定的私有 IPv4 与真实 MAC；HA 必须能收到 ICMP 回应、直接读取邻居 MAC。多台设备需逐台添加。

短信登录默认 MQTT；手工令牌路径保留 REST 默认值。两种传输都依赖奥普云。

| | REST | MQTT |
| --- | --- | --- |
| 登录来源 | 短信验证码（实验）或已有令牌 | 短信验证码（实验）或已有令牌 |
| 持久保存 | 账户令牌、设备标识和名称 | MQTT 凭据、设备/IP/MAC；不保存手机号、验证码或账户令牌 |
| 日常访问 | 账户 HTTPS 与云 MQTT | 云 MQTT 和局域网核验，不调用账户 HTTPS |
| 普通断线 | 自动有界重连 | 复用缓存凭据自动有界重连 |
| 凭据被拒绝 | 重新授权 | 短信重新登录或输入新账户令牌，重新取得 MQTT 凭据 |

当前没有验证可用的账户 refresh-token 接口；短信重新登录仍需本人验证码，不宣称无人值守续期。本地 MQTT 也尚无可用协议证据。重新授权核对原设备归属，成功后保留配置项和实体身份。

跨 VLAN、NAT 或桥接容器环境可能无法读取邻居 MAC。Linux 读取 `/proc/net/arp`，macOS 使用系统 `ping`/`arp`；Windows 原生环境未验证。不要通过删除校验或关闭 TLS 解决。

HA 配置与备份内的凭据仍需保护；输入框隐藏不等于独立加密。详见 [隐私与安全](SECURITY.md)。

## 控制行为与限制

- 只接受已识别功能和参数。控制前读取当前状态，确认在线，按设备串行合并指定字段。
- 使用独立请求标识及设备新回报确认执行；云端接受请求不直接等同于设备执行成功。
- 超时、断线或回执不明时不自动重发控制。读取断线可以进行一次有界重连。
- 单独调温不启动制热；AI 关闭时不能调节其目标温度。关闭温控只停止 AI 模式。
- 未识别的预约编码保留原值，不猜测写入。换档保持实际时长；超过新档上限时要求显式给出兼容时长。
- 云端状态存在延迟；30 秒轮询和局域网检查不能保证立即发现断电，也不证明设备即时热状态。

历史记录包括两台同型号设备的控制检查及一次约 10 分钟换气预约自然结束，不能外推到其他型号、全部预约周期或长期稳定性。账户自动续期仍未实现。原长期凭据观察曾提前失败，之后有限次数的成功查询不构成持续无故障证明。本次新增短信与云端只读链路验证，没有重做物理控制、完整预约周期或长期验收；新候选未安装到现有 HA，局域网核验和该候选实际 HA 重载仍待单独验证。

## 开发与复验

完整框架测试需要 Python 3.14 和独立虚拟环境：

```sh
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-test.txt
python scripts/verify_project.py
python scripts/run_tests.py
```

只运行不依赖 HA 框架的客户端/编解码测试：

```sh
python -m pip install -r requirements.txt
python scripts/run_tests.py --unit-only
```

测试在临时目录启动隔离的 HA 对象，使用合成配置和 mocks；测试入口阻断外部网络连接，不读取现有 HA 配置或调用真实设备。安装依赖、漏洞数据库查询需要互联网，与测试执行分开。

```sh
python -m pip install -r requirements-audit.txt
python -m pip_audit --no-deps --disable-pip -r requirements.txt
```

上述漏洞查询仅覆盖两个直接安装依赖，不是整个 HA 环境的安全保证。依赖、许可和本次查询结果见 [第三方说明](THIRD_PARTY_NOTICES.md) 和 [审阅报告](docs/REVIEW.md)。
