# 登录与 MQTT 凭据生命周期

本候选提供手机号验证码登录、首次获取云 MQTT 凭据，以及短信重新授权流程。**2026-10-28 已完成真实短信登录、两台设备身份匹配和云 MQTT 只读连接/重连验证，无需手工抓取账户令牌。此证据不等于无人值守续期已实现。**

## 已完成的真实链路

先完成一次只读设备发现验证；随后另开一个临时私有会话，在同一次登录中完成整条链路。两次短信均由本人在页面提交，程序没有自动重发。

| 完整链路会话 | 实际结果 |
| --- | --- |
| 短信请求与验证码登录 | 请求1次，服务端确认，本人输入验证码，登录成功 |
| 设备发现 | 发现2台，两台标识均与原小程序设备一致 |
| 领取 MQTT 凭据 | 1次，后续连接和重连复用这一套凭据 |
| 新建连接 | 4次：两台初连，再分别重连 |
| 关联查询 | 10次 Shadow GET，全部取得匹配响应 |
| 连接隔离 | 关闭一条实验连接时，另一条实验连接仍能读取 |
| 控制与 HA | 控制0次；未访问现有HA；只关闭本实验创建的连接 |
| 敏感信息 | 手机号、验证码、账户令牌与MQTT凭据未写入验收文件 |

证据：[脱敏完整链路结果](../audit/real-cloud-mqtt-readonly.json)。验证调用本候选的短信客户端、账户客户端和 ShadowSession，另加只允许自有设备 `/shadow/get` 的发送守卫。局域网在线状态没有在这次表单中核验，不把云 Shadow 响应等同于设备在线或物理执行。真实 HA 配置流程整体安装/重载仍未进行；121项真实框架隔离测试与这次云端实测分别记录。

## 请求来源

来源为本人奥普智享家小程序版本 29 的静态请求定义，不执行厂商代码。

| 操作 | 方法与路径 | 字段 |
| --- | --- | --- |
| 发送短信 | GET `/applicationApi/authserver/auth/user/terminal/smscode` | areaCode、固定客户端选择值 appKey、phoneNum、type=LOG |
| 验证码登录 | POST `/applicationApi/authserver/auth/user/terminal/loginByPhone` | areaCode、appKey、phone、randomCode |
| 微信快捷登录 | POST `/applicationApi/authserver/auth/user/terminal/wx-quick-login` | appKey、微信一次性 code/jsCode |

客户端选择值不是用户账号密钥。本实现没有复制厂商 App-Authorization 签名函数或内嵌签名材料；所需字段按观察到的请求契约重新编写。

小程序当前只在测试环境条件下显示手机登录入口。生产云接口对没有手机号的 SMS 请求，以及字段完整、但手机号/验证码为空的登录请求，均返回业务码 1310“手机号为空”。没有发送真实手机号、短信、验证码、账户令牌或应用签名。这段为空参数研究阶段的历史记录。随后本人通过私有表单完成了正向验证：真实短信送达、验证码兑换及两台原设备归属均通过，证据见 `../audit/real-sms-device-discovery.json`。未复制号码、验证码或令牌。

## 使用与隐私

在 HA 添加集成时选择“手机号验证码（实验）”。输入奥普智享家绑定的中国大陆手机号，点击提交将请求一条验证码；再输入收到的六位验证码。

成功兑换后，组件使用返回的账户令牌发现支持设备。MQTT 模式再获取云凭据并核验局域网身份，最终配置只保存 MQTT 凭据和设备/IP/MAC，不保存手机号、验证码和账户令牌。REST 模式需要保存账户令牌，表单已明确说明。

手机号在本次配置流和内存限频表中临时保留，不写入配置项；验证码只作为一次调用参数。云端 GET 短信接口把手机号放在请求 URL，组件不会记录它，但宿主或额外代理的请求日志需要自行保护。

同一手机号 60 秒内不再请求短信，包括并行配置流；本地验证码流程最多 10 分钟、最多提交 5 次。短信请求超时可能已经送达，显示不确定状态并允许输入已收到的码，不自动再发。网络失败、登录失败和凭据替换不自动重复发送设备控制。

凭据被拒绝进入 HA 重新授权时，可选择短信登录或手工新令牌。短信登录后仍须确认原设备属于该账户；错误账户不能替换原配置，成功重新授权保留配置项和实体身份。

## 是否需要一直刷新

账户 JWT 和 MQTT 凭据不是同一种认证材料。历史账户 JWT 声明约 10 天有效期，不是已经独立验证的实际过期策略。MQTT 凭据返回中没有暴露可解析的到期字段；历史只读复核中，同一套凭据约 120.9 小时后仍能新建连接读取，期间没有刷新。

普通网络断开继续复用缓存凭据重连。AWS IoT 的连接期限和权限复核是服务端连接/授权策略，不等于客户端必须重新领凭据：[官方说明](https://docs.aws.amazon.com/iot/latest/developerguide/custom-auth-lambda.html)。不能因此承诺奥普凭据永久有效。

没有发现可确认使用的账户 refresh-token 契约。微信登录需要微信签发的一次性 code，短信登录需要本人收到的验证码。本候选不伪造 JWT、不重复使用旧微信 code、不内置共享签名密钥，也不把短信重新授权命名为完全自动续期。

## 本地 MQTT

历史检查中，设备常见 MQTT TCP 端口没有发现可用监听；只覆盖部分端口，不能排除 UDP、蓝牙或其他本地协议。本次未重新扫描设备、修改 DNS、替换证书、刷机或切断云连接。现有 MQTT 是奥普云 MQTT；启动一个本地 broker 不会自动让浴霸接受它。
